## Why

RedChef exposes public data reads and user/admin mutations through the same API surface. The mutation boundary must be explicit and consistent so a leaked or unauthenticated request cannot create, edit, delete, favourite, tip, or moderate content.

## What Changes

- Keep public GET reads, including `/api/trmnl/latest`, available without credentials.
- Require an authenticated RedChef user session plus a bearer API token for create, update, and delete operations.
- Add one-time-visible token creation and token lifecycle management for authenticated users.
- Preserve existing admin authorization and browser CSRF protections.

## Capabilities

### New Capabilities

- `api-authentication`

### Modified Capabilities

- `public-api-reads`

## Impact

The Go HTTP middleware, route registration, persistence migrations, token-management UI/API, and integration tests are affected. Existing browser sessions and public TRMNL polling must remain compatible. No real token is generated by this change artifact.
